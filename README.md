# 短線雷達 · 臺股 1–2 週波段觀察清單

一個會「每天自動跑」的網頁:收盤後用固定規則從上市股票與熱門 ETF 裡篩出一份
技術面觀察清單,存成靜態網頁給你每天看。全部用免費公開資料,免主機費用
(掛在 GitHub 上)。

**這不是選股神器,也不是投資建議。** 篩選邏輯就是均線、RSI、量能、相對
大盤強弱、公開三大法人買賣超這幾個很常見的組合,沒有做過嚴謹回測,過去
價量表現也不保證未來報酬。把它當成「幫你先縮小範圍的清單」,實際進出場
還是要靠你自己判斷。

---

## 架構

```
scanner.py          <- 每天跑一次的資料流程(見下方「怎麼運作」)
docs/index.html      <- 前端網頁(讀取 docs/data.json 顯示排行榜)
docs/data.json        <- scanner.py 產生的結果,前端讀這個檔案
docs/snapshots.json   <- 每日清單快照,用來做昨日/5 日回顧
.github/workflows/daily.yml  <- 排程:收盤後自動跑 scanner.py 並發布
requirements.txt      <- Python 套件需求
```

### 怎麼運作(四階段)

1. **全市場快照** — 優先打證交所官網盤後 `STOCK_DAY_ALL`(當日),OpenAPI
   當備援(常慢一天)。一次拿到該交易日所有上市股票與 ETF 的收盤價、漲跌、
   成交量/成交金額。網頁上的現價、漲跌幅、`as_of` 交易日都用這份快照。
2. **流動性初篩** — 用今天的成交量/成交值、股價區間先縮小到候選池
   (預設約 300 檔),並剔除處置股與變更交易(全額交割/分盤)。槓桿/反向 ETF
   不納入。`MAX_PRICE` 只排除極端高價股,不是用來判斷「有沒有漲多」。
3. **抓歷史資料算指標** — 對候選池用 yfinance 抓近 1 年日K,計算 5/20 日
   均線、RSI(14, Wilder)、ATR 延伸、量能比、相對大盤 5 日強弱。Yahoo 若缺
   當日 K 棒,用證交所 OHLC 補上。另抓 T86 三大法人當日與近三日投信。
4. **結構 / 擁擠百分位排序** — 各因子在候選池內改成百分位,拆成結構分
   (動能剛啟動)與擁擠分(動能已經走遠)。觀察排序 =
   結構 − 擁擠 × 0.5,大漲大跌另外降權,法人買賣超做加減分。大盤跌破 20MA
   時不發「強力推薦」。出場欄只追蹤過去 10 個交易日曾推薦的標的。

## 快速開始:部署到 GitHub(全自動每天更新)

1. **建立 repo**:把這個資料夾整個推到你自己的 GitHub repo(public 或
   private 皆可,private 的話 Pages 需要付費方案才能開,建議用 public)。

2. **開啟 GitHub Pages**:repo 的 `Settings → Pages`,Source 選
   `Deploy from a branch`,Branch 選 `main`、資料夾選 `/docs`,存檔。
   之後網址會長得像 `https://你的帳號.github.io/repo名稱/`。

3. **開放 Actions 寫入權限**:repo 的 `Settings → Actions → General →
   Workflow permissions`,選 `Read and write permissions`,存檔。
   (這樣排程跑完才能把新的 `data.json` commit 回 repo。)

4. **手動測試一次**:repo 的 `Actions` 分頁 → 選 `每日掃描臺股短線觀察清單`
   → `Run workflow`,跑完檢查 `docs/data.json` 有沒有更新、Pages 網頁
   有沒有正常顯示。

5. 之後平日(週一~五)台北時間 16:00 會自動跑一次。想改時間就改
   `.github/workflows/daily.yml` 裡的 `cron`(注意 GitHub Actions 的
   cron 是 UTC 時間;目前 `0 8 * * 1-5` = 16:00 台北)。

## 篩選邏輯與評分

動能延續本身是 1–2 週持有期的合法因子。這裡要分開的是「剛啟動」
跟「已經走完」,不是把動能從清單裡拿掉。

**結構分**(百分位加權):趨勢對齊 40%、RSI 健康度 35%、尚未過度延伸 25%。
RSI 用 Wilder 平滑,健康度是約 58 為峰的山形,不是 50–70 整段給滿分。

**擁擠分**(百分位加權):量能、相對大盤超額、當日波動、ATR 延伸各 25%。

**觀察排序** = 結構分 − 擁擠分 × 0.5 − 額外降權 + 法人加減分。接近漲停或跌停
(≥9.5% / ≤-9.5%)降 25 分,今日大漲或大跌(≥7% / ≤-7%)降 12 分,並標成風險條件。
缺量能或相對大盤資料時,給中性百分位,但**不會**當成強力推薦條件通過。

清單上的「觸發條件」只表示規則有沒有被點亮,不是進場時機。風險條件
(接近漲停、今日大漲、今日大跌、延伸過遠、短線過熱、放量長陰)用紅色標籤分開顯示。
個股與 ETF 會分開標示;ETF 使用證交所 ETF 檔位(50 元以下 0.01、以上 0.05)。

**資料來源**:現價/漲跌/交易日 = 證交所盤後快照;指標 = Yahoo Finance 歷史 K 線
(缺當日則用證交所 OHLC 補上);法人 = T86。頁面會寫明來源。

**昨日清單回顧**:每天把清單存進 `snapshots.json`,隔天用證交所收盤價
算清單平均 1 日報酬,對照證交所大盤日報酬。`as_of` 用快照交易日,不是執行當日。
這是規則的公開對帳,不是回測報告;要累積至少一個交易日才看得到。

**懶人包分級**(同一套指標,另外切進出場):

- 強力推薦 / 分批進場:結構對了還要有量能跟上、近 5 日沒明顯輸大盤。
  沒人買的冷清不能當成「剛啟動」。大盤在 20MA 之下不發強力推薦。
- 觀望:好壞參半,或量能/相對強弱過弱
- 部分賣出 / 出清:**只追蹤過去 10 個交易日本系統推薦過的標的**
  (達停利、停損、跌破 20MA,或當日技術面轉弱)

**進出場區間**:只對「強力推薦／分批進場」計算。進場等回檔至 5 日均線附近;
停損預設 1.5×Wilder ATR,且不少於 max(1×ATR, 2.5%),避免停損近到不夠摩擦成本。
停利為 1.5 倍與 2.5 倍風險(R)。
參考持有 5–10 個交易日,收盤跌破 20 日均線視為結構失效。

## 客製化

- **調整篩選門檻 / 權重**:都在 `scanner.py` 最上面的參數區
  (`MIN_TRADE_VOLUME_SHARES`、`STRUCTURE_WEIGHTS`、`CROWDING_PENALTY` 等),
  改完直接重跑即可,不用動邏輯本身。
- **想涵蓋上櫃(TPEx)股票**:目前 `STOCK_DAY_ALL` 只涵蓋上市,上櫃股票
  要另外接 TPEx OpenAPI 的對應端點,是同樣的邏輯但欄位命名不同。
- **想換資料來源**:如果 yfinance 抓資料不穩定,可以換成
  [FinMind](https://finmind.github.io/) 的 `TaiwanStockPrice` 資料集
  (免費額度 300–600 次/小時,註冊後更高)。

## 限制與注意事項

- 這是「收盤後」的每日批次更新,不是即時盤中資料,不適合當沖使用。
- 篩選邏輯沒有做過嚴謹回測,權重是憑經驗設的合理起點,不是最佳化結果。
  頁面上的「昨日清單回顧」只是逐日對帳,不是完整績效報告。
- 現價走證交所、歷史 K 線走 Yahoo;若 Yahoo 缺當日,會用證交所 OHLC 補上。
- yfinance 抓取的資料偶爾會有缺漏,`scanner.py` 對抓不到足夠
  歷史資料的股票會直接跳過,不會硬湊資料。
- 法人只用公開 T86(當日與近三日投信連續買超),不是即時分點或券商分點。
- 處置股與變更交易會剔除;注意股仍可能出現。ETF 折溢價目前沒有穩定的
  免費 JSON 端點,這版先不標。
- TWSE API 的欄位命名偶爾會微調,`scanner.py` 在對不到預期欄位時會在
  Actions 的 log 裡印警告,方便排查。

**再次提醒:這不是投資建議。** 短線交易風險本來就高,任何買賣決定都是
你自己的判斷與責任。
